MauriOne — Admin authorization snippet (DO NOT deploy as a full replacement without merging existing rules)

Use an `admins/{uid}` document with `{ active: true }` for authorized administrators.
The client dashboard checks the same document, but the Firestore rule is the real security boundary.

Example helper + ads rule to MERGE into the existing firestore.rules:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    function isAdmin() {
      return signedIn()
        && exists(/databases/$(database)/documents/admins/$(request.auth.uid))
        && get(/databases/$(database)/documents/admins/$(request.auth.uid)).data.active == true;
    }

    match /admins/{uid} {
      // An authenticated user may only read their own admin marker.
      // Create/update/delete admin markers from Firebase Console or a trusted backend only.
      allow read: if signedIn() && request.auth.uid == uid;
      allow write: if false;
    }

    match /ads/{adId} {
      allow read: if true;
      allow create: if signedIn()
        && request.resource.data.ownerId == request.auth.uid;
      allow update, delete: if signedIn()
        && (resource.data.ownerId == request.auth.uid || isAdmin());
    }
  }
}

Important: MauriOne has other Firestore collections/flows. Preserve their existing rules when merging this snippet.
